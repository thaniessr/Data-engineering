SSH stands for Secure Shell.

SSH is a network protocol that allows you to connect to and control another computer securely using a terminal or command line.

Important SSH commands
Command	Purpose
ssh localhost	               -Connect to your own computer
ssh username@192.168.1.10	   -Connect to another computer using its IP address
sudo systemctl status ssh	   -Check whether the SSH service is running
sudo systemctl start ssh	   -Start the SSH service
sudo systemctl restart ssh   	-Restart the SSH service
exit	                        -Disconnect from the SSH session

Generate SSH keys:
ssh-keygen -t rsa -P "" -f ~/.ssh/sshkey_rsa   or      ssh-keygen -t rsa

Explanation:
- ssh-keygen — Generates SSH keys.
- -t rsa — Specifies the RSA key type.
- -P "" — Sets an empty passphrase.
- -f ~/.ssh/id_rsa — Specifies where to save the keys.

This generates two files:
File	Purpose:
~/.ssh/id_rsa	      Private key; keep it secret
~/.ssh/id_rsa.pub	   Public key; can be shared with the destination account

If you already have SSH keys, don't overwrite them. Check first:

Configure core-site.xml:
nano $HADOOP_HOME/etc/hadoop/core-site.xml

Replace its contents with:
<?xml version="1.0"?>
<configuration>
    <property>
        <name>fs.defaultFS</name>
        <value>hdfs://localhost:9000</value>
    </property>
</configuration>

Configure hdfs-site.xml:
nano $HADOOP_HOME/etc/hadoop/hdfs-site.xml    - Open the file  

Use the following configuration:
<?xml version="1.0"?>
<configuration>
    <property>
        <name>dfs.replication</name>
        <value>1</value>
    </property>

    <property>
        <name>dfs.namenode.name.dir</name>
        <value>file:///usr/local/hadoop/data/namenode</value>
    </property>

    <property>
        <name>dfs.datanode.data.dir</name>
        <value>file:///usr/local/hadoop/data/datanode</value>
    </property>
</configuration>

Purpose of these properties:
- dfs.replication = 1: Stores one replica of each data block because you're running a single-node setup.
- dfs.namenode.name.dir: Stores NameNode metadata.
- dfs.datanode.data.dir: Stores HDFS data blocks.
Important: Each XML file must contain exactly one <configuration> root element. Avoid adding a second root element, as this causes XML parsing errors.
